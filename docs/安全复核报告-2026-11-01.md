# TeamsGroupSentry v1.0.2 安全复核报告

## 1. 项目概况与审核边界

- 原生 JavaScript、Chrome Manifest V3 扩展（最低 Chrome 120），Node.js ≥20 内置 `node:test` 测试，Python 标准库 `zipfile` 打包；没有 React、Vue、服务器、Electron、iOS/Android 工程。
- 核心入口：`background.js`、`content.js`、`page-reader.js`、`lib/isolated-reader.js`、`lib/db.js`、`lib/recovery.js`、`lib/request-cache.js`、`lib/group-history.js`、`ui/dashboard.js`、`popup/popup.js`、`overlay/overlay.js`。
- `package.json` 的 dependencies、devDependencies、optionalDependencies、peerDependencies **均为空**；无 npm/pnpm/yarn 锁文件，无 Python/Go/Rust/Java/Podfile 依赖清单，也没有 vendored 第三方 npm 包。第三方直接依赖 **0**、间接依赖 **0**。不能虚构依赖版本或 CVE，也没有适用的“失维护/仿冒依赖”可标记。
- `npm audit --offline --no-package-lock --json` 返回 0 项依赖公告；`npm ls --all` 显示无第三方包。npm 官方说明该工具检查依赖树（<https://docs.npmjs.com/cli/commands/npm-audit/>）；本结果不代表业务代码不存在漏洞。由于没有第三方包，GitHub Advisory Database、OSV、NVD 中不存在可逐个按本项目**依赖名称+安装版本**交叉核对的对象，未编造 CVE。
- `manifest.json` 权限：`storage`、`unlimitedStorage`、`alarms`、`notifications`、`offscreen`、`scripting`；唯一主机权限 `https://teams.live.com/*`。未声明 `<all_urls>`、`externally_connectable` 或远程脚本。上述权限与现有功能对应；本次未擅自改变权限。
- **待确认的范围：** ZIP 不含 `.git` 历史、远程 GitHub Actions/CI、用户 Chrome Profile 或已登录 Teams 环境。因此不能声称已检查过提交历史的秘密、远端 CI 或真实网页互动。

## 3. 已直接修复的代码问题

### R-01 大量历史事件处理卡顿

- **修复前**：`lib/group-history.js` 的名单事件去重在处理每条提醒时遍历全部历史快照；“单人新增事件”又逐条遍历快照，人工确认也在结果中反复搜索。事件足够多时总操作量近似 O(n²)，可能拖慢安全中心。
- **修复后**：先对群的快照变化建立时间索引、人员索引和类型索引，通过有序时间表和二分查找检测 ±30 秒的重复事件，并使用键控映射关联人工确认时间。总的记录处理成本主要是排序 O(n log n) 与线性索引构建。去重方向、原来的 30 秒和 30 天窗口及最多显示 300 项规则未更改。
- **验证**：`tests/group-history.test.cjs` 新增 1,600 条历史事件压力场景，断言每条名单数组不会被反复读取；原有历史用例仍通过。此外以修复前源码作为对照，2,500 组随机事件的列表结果完全一致（一次性本地对照，未计入 npm test 项数）。

### R-02 ID 组合冲突

- **修复前**：通过 `id1,id2|id3` 一类直接拼接字符串作为去重标识，若 ID 内部包含逗号或竖线，可能使不同 ID 数组产生相同字符串。
- **修复后**：对 `[新增 ID 数组, 减少 ID 数组]` 使用 `JSON.stringify` 形成结构化去重键，避免分隔符歧义；同时把“最多取前 100 个唯一 ID”的处理改为有界迭代，减少超大数组的瞬时内存分配。
- **验证**：新增“分隔符不同、拼接后相似”的两组 ID 仍生成两条独立历史变化的测试。此变更**不改变 Teams ID、人员身份状态或后台数据库记录**。

### 实际文件修改

1. `lib/group-history.js`：优化去重索引和去重键生成，限制内存放大。
2. `tests/group-history.test.cjs`：增加 2 个安全回归用例。
3. `CHANGELOG.md`：同版本修复说明。

## 5. 硬编码凭据与敏感文件

- 对源码、测试、配置、文档及已生成的文本报告进行模式扫描，覆盖 PEM 私钥、AWS AccessKey、GitHub Token、Slack Token、Discord Webhook、带凭据连接串和关闭 TLS 验证的典型模式；**没有发现明确命中的实际秘密**。模式扫描有漏报可能，不代表全面历史秘密扫描。
- `.gitignore` 包括 `.env*`、`profile/`、`profiles/`、`IndexedDB/`、`User Data/`、备份文件、日志等。当前工作目录无 `.env` 文件，源码 ZIP 无 `.git`，因此**无法验证敏感文件是否在历史提交中出现过**。
- 因未发现需迁移的现成密钥，未添加不必要的 `.env.example`，也未将口令写入扩展代码。如发现历史泄露，必须在对应平台**作废并轮换密钥**，删除源码中的凭据并不足够。

## 6. 需要开发者决定和后续建议

1. **本地加密方案 A（建议当前继续）**：采用浏览器隔离及设备全盘加密保护本地记录，保留无人值守巡检。**方案 B**：增加数据库口令加密、开机解锁与旧数据迁移；提升设备文件被窃取后的保密性，但可能导致浏览器重启后后台无法自动读取，需明确授权设计，未自行实施。
2. **实时成员资格**：维持目前“观察时间 ≠ 实际进退群时间”，不自动用旧缓存修正真实人数。如要改变，需要先论证个人版 Teams 官方数据能力与授权范围，属于业务判断变更。
3. **仓库外审计**：需要提供真实 Git 历史/CI 工作流后才能覆盖提交历史密钥、代码签名、第三方 Action 完整 SHA 固定等。
4. **发布验收**：先导出加密备份，再覆盖原扩展目录、重新加载并刷新 Teams。真实 Teams 登录环境的成员变化、退群与批量审核需现场验证。
