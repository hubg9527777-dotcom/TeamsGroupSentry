# TeamsGroupSentry 1.0.1 安全审核报告（2026-10-16）

## 审核基准与范围

基准：用户上传的 `TeamsGroupSentry-ym.zip`，而非此前发布的源码快照。仅修改审核工作副本；原本地 Mac 路径、浏览器数据及 GitHub 仓库均未操作。项目是纯 JavaScript Chrome Manifest V3 扩展，使用 IndexedDB、Chrome 扩展 API、Web Crypto API 和 Node.js 自带测试工具。`package.json` **无 dependencies / devDependencies**，不存在第三方运行包或间接依赖；没有 package-lock、pnpm-lock、yarn.lock 或其他语言包管理文件。开发环境要求 Node 20+，版本固定 `1.0.1`。

检查覆盖：`manifest.json`、后台 service worker、Teams 页面脚本与缓存读取器、好友/聊天请求判定、身份与账号隔离、事件/人员/群数据库与恢复、加密备份、弹窗与安全中心 DOM 构造、全部测试脚本、打包脚本、文档和常见凭据模式；检查所有 JS/CJS 语法、npm test，以及尝试 Chromium 浏览器集成测试。按 Chrome 官方安全建议重点审查扩展消息来源、最小权限和不可信网页 DOM 的处理。

本次静态代码审查**未确认可直接利用的 Critical / High 漏洞**；这不代表没有任何安全缺陷。`unlimitedStorage`、`scripting`、`offscreen` 等权限已有功能用途，但以后仍建议逐项复审最小权限；目前不改变权限以免破坏已有功能。

## 修复详情与验证

- `tests/serve.cjs`：测试 HTTP 服务限制为确需的根文件及 `tests/lib/ui/popup/overlay/icons/offscreen` 中允许的静态后缀；只准 `GET/HEAD`，禁止隐藏文件与 `../`，使用 `realpath()` 防逃逸，避免被当作任意本地文件服务器。
- `tests/serve-security.test.cjs`：新增允许与拒绝路径两项专项测试，覆盖普通测试入口、`.env`、`.git`、目录穿越、非法 URL、备份和私有文件。
- `tests/request-notice.test.cjs`：虚构 `crypto.subtle.digest()` 改用内置 `createHash('sha256')`，保持 SHA-256 内容一致、消除测试时序不稳定。生产内容脚本、加密备份不受影响。
- `tests/build-packages.py`：阻止打包 symlink、无效文件和项目根外文件。

测试：原始 `npm test` **121/124 通过、3 失败**；修复后 `npm test` **126/126 通过、0 失败**，另外请求通知专项测试连续跑 3 次均为 **25/25 通过**。检查所有 JS/CJS 语法、JSON 清单与 ZIP 完整性。Chromium 测试**未成功执行**，不能算通过。`npm audit` 因没有 lock 返回 `ENOLOCK`。

## 密钥、依赖与隐私

已扫描源码、配置、注释、测试和文档的常见 API Key、Token、GitHub Token、云密钥、PEM 私钥、Webhook、机器用户路径模式：本次**未发现具体硬编码凭据**。本次 ZIP 无 `.git` 历史，**不能判断过去 GitHub 历史是否提交过秘密**，正式发布前需要再审查 Git 历史和 GitHub Secret Scanning。若历史上曾泄露真实密钥，必须在提供商处作废并轮换，仅从源码删除不够。

项目当前不需要 `.env` 配置；`.gitignore` 已忽略 `.env*`、浏览器数据与常见备份格式。没有第三方 JavaScript 库，只有 Chrome API / Web Crypto / Node 内置模块；不存在可以归责于某个实际安装包版本的已知 CVE，勿伪造漏洞编号。

个人资料仍保存在浏览器本地 IndexedDB。Teams 网站缓存不是微软服务器的权威成员清单；识别不到请求者完整 ID 时，安全提醒必须使用“身份待核实”措辞而不是声称已确认诈骗。

## 开发者需要决定

1. **好友请求覆盖策略（推荐：保持当前安全边界）**：选 A，仅观察当前可见请求并增加“检测范围有限”提示；选 B，研究微软正式身份/消息接口的可用性和新增授权，再讨论是否实现更完整的覆盖。**不建议**放宽到仅凭历史缓存自动认定存在请求。
2. **本地自动恢复点加密（推荐：暂保留，单列优化）**：选 A，依赖 Chrome 资料隔离 + 系统磁盘保护，文档明确风险；选 B，设计用户密钥/操作系统密钥方案后迁移。强行加密但没有自动可用密钥，会破坏断电和升级恢复能力。
3. **GitHub 发布时机**：先在两个独立 Chrome 资料测试本次改动与好友请求、群/人员识别，再提交 `v1.0.1`。当前工作副本**尚未推送或修改 GitHub**。

## 结论

上传代码经可复现的静态审计和 Node 回归测试，目前未确认 Critical / High 级直接可利用漏洞；修复了测试工具文件暴露面、打包泄密边界以及异步测试误判。生产核心监控/审核/身份绑定没有擅自改动，**公开版本仍是 1.0.1**。待真实 Teams 浏览器验收和开发者决定上述风险取舍后，才建议正式上传 GitHub。
